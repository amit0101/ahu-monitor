07 RUL + failure probability prediction.py

  • Runs only when entity health ≤ 0.70 and ≥ 30 points; fits the most recent 30% of history.
  • Fits h = a·e^(bt) + c (a∈[0,2], b∈[−5,0], c∈[0,1]) and h = mt + c; keeps the lower-MSE fit. Exp needs a valid RUL; linear with m ≥ 0 → no RUL.
  • Projects in 0.5-day steps up to 180 d. RUL = first h < 0.15; also days to 0.70 / 0.40.
P(fail) = 1 / (1 + e^(6(h − 0.4))) [+ 0.3·(1 − RUL/30) if RUL < 30 d]
h = 1 → 0.03 · h = 0.4 → 0.50 · h = 0.15 → 0.82 · clipped at 1

08 Alerts & recommendations fusion.py

Alert fires only when all hold:

  • sim_day ≥ 20 (training gate)
  • ≥ 5 consecutive degraded ticks (debounce)
  • state ≠ last fired state (edge-triggered)
  • ≥ 3 sim-days since this entity's last alert (cooldown)

Back to NORMAL resets counter and edge. Lists capped: active 50, history 200.

Recommendations are sticky per entity: raised on first WARNING/CRITICAL with a known fault, retired only on NORMAL.

CRITICAL → critical RUL < 15 d → high WARNING → medium
Sorted by priority, then RUL.

!! Known quirks (as coded)

  • Acceleration is quadratic in speed: speed scales both Δday and tick rate, so "50×" runs at ~2500×.
  • IF after a jump: training buffer fills only on live ticks (pre-roll skips _iso_score), so IF needs ~100 live observer calls (~12 s) to train. Buffer keeps growing after training.
  • Diagnosis keys z by SensorKind: multiple TEMPERATURE sensors overwrite each other (last wins); POWER is not in the vector.
  • _failure_probability docstring says 0.73 / 0.99; the formula gives 0.50 / 0.82 (see 07).
